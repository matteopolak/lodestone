# Worldgen resource front ends

## What it is

The 26.3 resource front end decodes block states and provider resources into the existing canonical state and typed vegetation representations before generation. Its numeric backend provides an isolated 32-bit arithmetic arena during migration to the current integrated-world generator; neither subset claims that a complete natural-world bundle can execute.

## How it works

`frontend26_3::parse_state` accepts a compact block name or an object with `id` and optional `properties`. Omitted properties use the block's registered defaults. Every supplied property is validated against the canonical state census, so an unknown property or value cannot silently select a default state.

`frontend26_3::ProviderBaker` separates holder references from direct documents. A string passed to `bake_holder` identifies a `block_state_provider` resource; a string inside the resource's direct document identifies a block state. The lookup callback receives a canonical namespaced resource identifier. Named providers are resolved once and cached as typed values. Recursive references, excessive nesting, missing resources and unsupported discriminators return `FrontendError` with a resource path.

Simple, weighted, supported rule-based and weighted-source randomized-integer providers bake into `BlockStateProvider`. Randomized properties become validated canonical-state arrays before placement. Rule providers preserve their optional-result semantics, including no result when no rule or fallback matches. Consumers requiring the current world state on a missing result must supply that behavior explicitly. Nullable nested rule branches are rejected because the current executor does not continue to later rules after an empty child result.

The provider representation currently cannot preserve the random draw count of a randomized-integer provider with a simple source: its weighted-source executor draws a selection even for one entry. That source form is therefore rejected. Noise, dual-noise, noise-threshold, rotated, random-block and copy-properties providers are also rejected until their exact execution contracts are supported. Supported predicate tags are currently the two ground-replacement tags used by the bundled tree providers; other tags and predicate types fail explicitly.

The density schema has a separate numerical compatibility boundary. The 26.3 scalar and volume arithmetic paths use 32-bit float operations, while the old density evaluator uses 64-bit floats. Even addition distinguishes them: `16777216 + 1` rounds to `16777216` in 32-bit float and remains `16777217` in 64-bit float. Interpolation also carries per-node cell dimensions, including a 16-by-1 surface-level node. Renaming JSON fields or expanding new arithmetic into the old evaluator cannot establish parity.

`engine::release26_3::Program` resolves the supported density subset into an immutable typed arena. `EvalWorkspace` is allocated once and reused for scalar sampling, with no JSON, resource lookup, hashing or allocation per sample. References share node identities. Pure-node memo entries include the sample epoch and exact block position. Explicit cache nodes and their ancestors bypass that memo because another branch can replace a retained volume during the same query. Lerp endpoints, range branches and zero-valued multiplication/division inputs evaluate only their required children. Each arithmetic operation rounds as a 32-bit float before its parent consumes it; signed zero and NaN handling are explicit for minimum, maximum and sign operations.

The numeric subset supports constants, addition, subtraction, multiplication, division, minimum, maximum, absolute value, square, cube, negative scaling, reciprocal, negation, squeeze, sign, clamp, lerp, range choice, clamped gradients, coordinate slices, named normal noise, the three coordinate-shift noise forms, node-local interpolation, explicit request caches, surface scans, interval selection, nested cubic splines, point-distance metrics, typed world-context inputs, blended octave noise and outer-island noise. These cover the discriminator families reached by ordinary three-dimension router, aquifer and material density roots. Unimplemented custom operations return load errors naming their discriminators. Registration coverage is not a production-world parity claim: request bindings, resident volume products and complete graph execution still need integration. This backend is migration groundwork, not an independently selectable second natural-world generator.

`Program::parse_with_context` accepts a `BuildContext` containing the seed, random algorithm and separate density/noise resource lookups. It validates noise parameters and retains each seeded named sampler once. The `noise` module keeps coordinate scaling, offsets, frequencies and normalization in double precision, but rounds lattice fractions, gradients, interpolation, layer amplitudes and ordered accumulation to single precision. Both precision domains are necessary; casting the old noise result to single precision is not equivalent. Named Nether temperature and vegetation resources retain their raw-seed schedules. The ordinary random primitives are shared because their initialization and draw contracts are unchanged.

Blended octave resources lower into three immutable smeared noise stacks and the arena's existing addition, clamp and lerp nodes. Equal parameter sets share these samplers at load time. The two limit stacks precede the selector stack in the random draw sequence; legacy mode starts from the raw world seed, while modern mode uses the named positional terrain stream. Smearing changes the gradient's vertical displacement but not the vertical interpolation weight. Scalar and bulk evaluation keep their distinct coordinate-scale grouping. Independent full-sampler fixtures cover all three dimension parameter sets, both random algorithms and large coordinates.

Outer-island noise retains one seed-bound permutation. It always uses the legacy raw world seed, consumes 17,292 draws and then constructs the permutation, including the three offset draws even though its offsets are zero. Simplex geometry and corner contributions remain double precision; the resulting sample and subsequent island-height arithmetic use single precision. Integer coordinate division truncates toward zero. Bulk evaluation samples each XZ column once and fills its Y range. Independent fixtures cover three seeds, negative coordinates, million-block coordinates and non-unit volume steps.

`Program::parse_roots_with_context` compiles router, aquifer and material inputs together. Consumers retain `RootId` handles and call `sample_root` or `sample_root_volume`; they do not create separate programs or caches per channel. Load-time axis analysis inserts zero-coordinate slices for uniform dimensions, collapsing bulk inputs before broadcasting. This shape transformation is part of execution semantics. Source holder identity survives until structural cache IDs are assigned; resource references disappear from the published arena.

An explicit cache slot owns one exact regular volume plus a separate last scalar point. Scalar reads first use a matching non-NaN point entry, then an on-grid value from the retained volume, then a fresh scalar evaluation. A volume read does not populate the point entry, and replacing the volume does not clear it. Bulk reuse requires the exact same volume descriptor. `EvalWorkspace::reset_request` clears these values while retaining allocations when immutable world/context inputs change. There is no persistent per-coordinate map.

`EvalWorkspace::bind_context` retains an `Arc<dyn RequestContext>` for the whole request and invalidates retained cache values without discarding prepared storage. The embedding generator supplies typed blend-alpha, blend-offset and structure-density inputs with separate scalar and whole-volume methods, plus a density transform. Context-sensitive nodes and their ancestors bypass generic memoization. Alpha and offset have XZ domains; structure density has XYZ domain; density transformation preserves its input's declared domain. The transform consumes the already evaluated input and visits bulk elements in y-fast order. `EmptyContext` explicitly selects alpha one, offset/structure zero and an identity transform. Omitting the binding is an error when a context node executes, not an implicit empty-world assumption. Real structure and neighboring-world blending implementations remain the embedding generator's responsibility.

Point-distance metrics subtract integer coordinates with wrapping before converting to single precision. Euclidean squared distance rounds each product and sum; Euclidean distance takes the square root of that rounded sum. Manhattan and maximum-axis distances retain their ordered float operations. The bulk form traverses the regular coordinates in the same y-fast layout. A large-coordinate fixture distinguishes float products from a late-rounded double calculation.

Scalar noise fixtures include three seeds, constructor offsets and permutation prefixes, large-coordinate wrapping, two-octave seed schedules, and asymmetric shift mappings. Their expected values come from a bounded independent interpreter of cached release bytecode plus independent normalization arithmetic. A late-rounding negative control was observed to disagree at seven of nine lattice samples. These fixtures do not establish bulk-volume, interpolated terrain or end-to-end world parity.

`SampleVolume` describes positive-step regular coordinates in y-fast, then x, then z order. `NoiseSampler::add_volume` adds into caller-owned storage and combines each layer's coordinate scales and amplitude before lattice evaluation. The bulk lattice path retains horizontal gradient terms while the y lattice cell is unchanged. An independent twelve-point bulk witness distinguishes this amplitude grouping from a scalar loop at four points.

`Program::sample_volume` dispatches over the same node and noise arenas. Prepare `EvalWorkspace` once with the request volume shape and an explicit scratch budget in float elements. Planning covers intermediate grids, worst-case coordinate alignment, scalar interpolation corners and spline coordinate buffers; the loader computes peak live buffer counts. Sampling never grows storage. This scratch is not a second cache hierarchy. Graphs without scalar scratch requirements are ready at construction; interpolation and nonconstant splines require preparation, and the single scalar `sample` API returns an error when storage is insufficient. Preparation is not a per-coordinate operation.

Bulk arithmetic evaluates complete child buffers: multiplication and division do not inherit scalar zero short circuits, while lerp still selects exact endpoint values after evaluating its buffers. Slices and rotated shifts transform regular volumes before broadcasting. Interpolation retains each node's horizontal and vertical cell sizes. Scalar queries bypass on-grid interpolation or sample a bulk corner grid and interpolate x/y/z. Bulk interpolation interpolates z then x, computes a vertical increment and repeatedly adds it down each cell column; arbitrary steps expand to block resolution before gathering. Independent fixtures cover negative coordinates, non-block steps, aligned bypass and 16-by-1 cells, including a scalar/bulk one-bit rounding discriminator.

Surface scans round the upper bound down to a cell boundary and test descending scalar density samples strictly above zero. Their bulk path first fills upper bounds, then scans columns while sharing the request's cache state. It requires a one-layer Y volume. A 16-by-1 interpolated surface root supports resident one-layer bulk sampling; an off-grid scalar interpolation still requests two Y corner layers and returns the surface scan's explicit shape error. Do not hide this boundary by changing scalar interpolation or adding an unauthenticated inner slice.

Interval selection keeps nondecreasing thresholds, including repetitions; equality advances to a higher interval and NaN selects the last function. Scalar execution evaluates only the selected function, while bulk execution evaluates input and every function buffer in order. Nested splines use float locations, derivatives and intermediate arithmetic. Their scalar coordinate memo is local to one spline invocation; bulk coordinates are filled as whole volumes only when first needed by a nested branch. Those buffers are temporary scratch, not persistent coordinate caches. Independent asymmetric spline fixtures distinguish float arithmetic from late rounding.

`frontend26_3::MaterialBaker` resolves material rule and condition holders into the existing surface control-flow representation. Its typed graph retains density-root ordinals and load-time noise/random resource bindings; `MaterialInputs` supplies the current request's samples and conditions. Collected density documents join the same multi-root numeric program before execution. Optional ore placement can continue into later material rules when it returns no state. Production surface-context binding remains separate from successful ingress; see [surface control flow](worldgen-surface-cfg.md).

## How to change it

Add state or provider schema support in `frontend26_3` and keep resource resolution at this boundary. Extend the shared typed executor only after confirming operation order, random consumption and optional-result behavior. Each new discriminator needs a positive fixture plus malformed and unsupported controls. Do not map an unknown predicate to an always-true predicate.

The integrated generator must pass its current bundle's provider lookup and retain the resulting typed objects. Adding a public module alone does not wire a natural-world generator: feature parsing, material rules, remaining density operations and all three dimension constructors still need migration. Keep one production cache authority, keyed by immutable bundle and execution policy. Once the complete current generator takes over, remove the obsolete natural-world assets and executor paths. Remote protocol compatibility is a separate concern and does not require retaining a second integrated generator.

## Configuration

The provider graph accepts at most 128 nested levels and 65,536 visited nodes per bake call, including randomized-property expansion and cached graph copies. The numeric arena also caps input depth at 128 and compiled nodes at 65,536. Weighted totals must fit a signed 32-bit integer and be positive. Callers pass all root/volume pairs to `EvalWorkspace::prepare_request` and a shared budget in float elements for scratch and retained cache buffers. `prepare_volume` is the convenience form for one shape across all roots. Invalid shapes, undersized output and insufficient preparation return errors. A prepared shape can be reused at other origins because planning covers worst-case alignment. Preparation does not reset the request's cache values; use `reset_request` at a real context boundary. There are no environment variables or runtime JSON lookups.

## Dependencies

The front end uses `serde_json` only at load time, `lodestone-data` for exact canonical state identity, and the existing `feature::vegetation::BlockStateProvider`, `BlockPredicate` and `IntProvider` execution types. The embedding application supplies the selected bundle's immutable resource lookup.
