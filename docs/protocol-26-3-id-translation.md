# 26.3 game-data ID translation

## What it is

`lodestone-v26-3::id_translation` maps append-only canonical block-state and item IDs to their 26.3 wire IDs. The shared codec uses the same selected identity maps before publishing gameplay values.

## How it works

The official reports are joined by block name plus state properties, or by item name. Existing canonical IDs retain their meaning; new identities append to the census. Typed `WireBlockStateId` and `WireItemId` values validate the 26.3 range and delegate translation to `GameDataVersion::V26_3`. All 35,723 states and 1,658 items resolve, including new content. A 26.2 egress query rejects the appended identities. Joining remains gated until the remaining body and presentation contracts are implemented.

Many numeric IDs changed. For example, `minecraft:water[level=0]` maps from canonical `86` to wire `89`, while `minecraft:stone` stays `1`. The final canonical state `35722` maps to wire `18402`; the old canonical final state `32365` maps to wire `35722`. Wire IDs cannot index canonical behavior tables directly.

Fixed registries use `FixedRegistryMappings`, injected into the shared dialect. Their callbacks translate a typed registry domain and an integer, without runtime registry-name lookup. The name callback accepts canonical IDs. The base dialect keeps its original wire bounds even when a canonical component or particle census grows. Synchronized registry holders instead use the actual session's captured entry order.

Component and particle identity tables share the append-only policy. Particle payload classifications are generated from registration bytecode and checked against both release reports; a shifted ID never implies an unchanged option layout.

## How to change it

Regenerate runtime identities through the [canonical census](./canonical-state-census.md) and [behavior union emitter](./data-behavior-codegen.md). The earlier compact-map tool remains a historical old-prefix drift fixture, not a linked runtime module:

```sh
python3 crates/versions/26.3/tools/gen_id_translation.py
python3 crates/versions/26.3/tools/gen_id_translation.py --check
```

Generate fixed registry maps and the canonical component/particle tables with `python3 crates/versions/26.3/tools/fixed_registry_maps.py --emit-data-tables`; add `--check` to verify generated bytes. `tools/class_contract.py` inspects cached jar bytecode without starting Java. Independent report and bytecode witnesses check shifted, appended, removed and wrong-release identities.

Translate at each wire boundary, including chunk palettes, block updates, entity metadata, and item-bearing packets. Do not renumber canonical IDs to make a packet fit. Static fixed mapping does not establish the body format of a component or metadata value.

## Configuration

There are no runtime flags. Tools read the cached official reports for both releases. `--base-jar` and `--latest-jar` select unpacked cached jars for particle classification. Runtime codecs receive the selected game-data profile and fixed callbacks through their dialect.

## Dependencies

The module uses `lodestone-data` for canonical `StateId` and `Item`. The official server reports are generation inputs; no report JSON or runtime string map is linked into the game.
