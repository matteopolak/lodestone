# Nether magma ore parity

## What it is

The Nether's `ore_magma` placed feature is a standard connected ore body in
the mixed underground-decoration step. It replaces eligible target blocks with
magma while sharing the same source order, raw feature index, and step-7 seed
as the neighboring non-ore entries.

## How it works

`NetherGenerator` keeps the placed entry in the source's raw step list and
routes its configured ore body through the standard ore writer. A source's
three-by-three read window can see earlier writes, and final magma cells are
folded into the target column or ordered spill stream. The focused test uses a
CARVERS-to-FEATURES JVM delta fixture at seed `42`, chunk `(5,3)`: the oracle
reported 508 changed magma cells, with ten witness coordinates retained in the
Rust fixture.

The negative-control resolver replaces only `ore_magma` in every biome feature
list with an unknown id. The other step-7 entries and their indices remain in
place, so a changed column demonstrates that this ore body is consumed by
production rather than merely parsed.

## How to change it

Keep `ore_magma` in the feature list even if its body changes; removing the
entry shifts later feature seeds. Update the external fixture if the source
seed or target chunk changes, and retain at least one witness above the global
lava boundary. Run the focused `nether_magma_ore` integration test after
changing ore placement or Nether source ordering.

## Configuration

The feature list comes from the bundled Nether biome documents. Its configured
ore document supplies the target rule, replacement state, size and placement
modifiers; no runtime flags alter the behavior.

## Dependencies

This slice depends on `lodestone-worldgen`'s shared ore writer,
`feature::region_view`, Nether source scheduling, and the bundled worldgen
tables. The checked-in fixture is generated by
`scripts/worldgen-oracle/NetherFeatureCellsOracle.java` through the repository
JVM oracle runner.
