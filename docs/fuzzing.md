# Fuzzing

## What it is

Two independent tracks. **Track A** (`fuzz/`, a `cargo-fuzz` workspace) is coverage-guided libFuzzer over pure parsing functions: packet framing and decoders, NBT, loot tables, block-state strings, fonts, region files, chat text, status JSON. **Track B** (`crates/lodestone-fuzz/src/differential.rs`) is a tick-aligned differential harness against a real vanilla server, finding wrong behaviour that never panics. The `proptest` decoder properties in `crates/lodestone-fuzz/tests/` run under plain `cargo test`; see [Fuzz harness](fuzz-harness.md).

## How it works

### Track A: `fuzz/`

`fuzz/` has its own `Cargo.lock` and an empty `[workspace]`, so nightly sanitizer flags never leak into `cargo build --workspace`; `rust-toolchain.toml` pins the nightly. Install `cargo-fuzz` once. Fourteen `[[bin]]` targets live in `fuzz/fuzz_targets/`:

- Packets: `v26_2_clientbound_decode` (`V770Adapter::handle_packet`), `v26_2_serverbound_decode` (`V770ServerProtocol::decode`), and `_by_id` variants of both that pick a real declared id by index and so reach decode bodies far more often; `packet_frame_codec` (`Codec::feed` + `next_packet`, cleartext and compressed). These reuse `lodestone-fuzz`'s `decode_clientbound`/`Family` plumbing.
- Data: `nbt_decode` (`read_named_nbt`), `loot_table_json` (`LootTable::from_json`), `block_state_string` (`state_id`), `unihex_font` (`read_hex_entries`), `anvil_region_parse` (`RegionFile::parse` over all 1024 slots, chained into NBT), `text_chat_json`, `text_chat_nbt`, `resource_pack_zip_source` (`ZipSource::from_bytes` then every entry), `status_json_model` (`parse_status_json` checked against an independent `serde_json::Value` model).

| recipe | what it does |
|---|---|
| `just fuzz-build` | ASan build of every target |
| `just fuzz-run <target> [flags]` | one target from `fuzz/corpus/<target>/` |
| `just fuzz-run-seeded <target> [flags]` | one target from committed seeds; prefer this |
| `just fuzz-repro <target> <artifact>` | replay a saved crash (path relative to `fuzz/`) |
| `just fuzz-smoke [seconds]` | bounded run of every gated target; what CI runs |
| `just fuzz-seeds-regen` | rebuild `fuzz/seeds/**` from `.cache/mc` |

Always pass `-max_total_time` and on a shared machine `-rss_limit_mb`: `just fuzz-run-seeded nbt_decode -max_total_time=600 -rss_limit_mb=1024`.

**Seeds.** `fuzz/seeds/<target>/` is committed; `corpus/`, `artifacts/`, `target/`, `coverage/` are gitignored. The `*-seeded` recipes pass `corpus/<target>` first so new inputs go there. Every seed comes from a producer this repo did not write, regenerated by `fuzz/seeds/generate-seeds.py` (a missing source is a hard error): captured wire payloads from `crates/versions/26.2/tests/fixtures/*.hex` for the packet targets, level/player/chunk NBT and one trimmed region from a vanilla save, the vanilla data pack's loot tables and text resources, strings spelled from the generator's `blocks.json`, a zip of vanilla `lang` files, and a real status response. `unihex_font` starts empty (no Unifont `.hex` offline).

**Crashes.** Failures save `crash-*`/`timeout-*` under `fuzz/artifacts/<target>/`; CI uploads them as `fuzz-artifacts`. Promote a real finding to a regression fixture following `crates/lodestone-fuzz/tests/fuzz_regressions.rs`; a crash left only in `artifacts/` gates nothing.

**CI.** The `fuzz` job runs `just fuzz-smoke 30` per push and PR: every target, at most 30 s or 10,000 executions, from seeds. It is a tripwire, not a campaign; `timeout-minutes` is 90 because the cold ASan build dominates. Leak detection is off (`-detect_leaks=0`). `fuzz/smoke-exclusions.txt` lists built-but-ungated targets with reasons; a stale exclusion or empty target set is a hard error, as are zero, negative, malformed or overflowing budgets. `python3 fuzz/test_smoke.py` tests this orchestration only. Execution rates span three orders of magnitude between targets, which is expected.

`lodestone_fuzz::catch` is a production `catch_unwind` boundary turning decoder panics into reported failures; `tests/catch_unwind_under_cranelift.rs` checks it under the default Cranelift dev backend and LLVM (`CARGO_PROFILE_DEV_CODEGEN_BACKEND=llvm`). Re-run the LLVM comparison after a toolchain bump.

### Track B: differential harness

- `Action`, `ScriptStep`, `Script`: the action sequence shared by hand-written live scripts and the generator.
- `WorldOracle`: one side (`apply`, `advance_tick`, `block_state`). `run_differential` applies each tick's actions to both sides before ticking either, compares a caller-named region after every tick and returns the first disagreement (`Divergence::tick` is 0-based, the tick just run). First-divergence matters because fluid spread and piston commit bugs are timing bugs that agree on final state.
- `differential::state_matches` gives the in-process side vanilla's matching semantics (`minecraft:water` matches `minecraft:water[level=3]`).
- `differential::rcon::RconOracle` (feature `rcon-oracle`) is a `WorldOracle` over any Source-RCON endpoint: real vanilla or our `IntegratedServer::start_rcon`. In-process oracles drive production entry points (`FluidModelOracle`, `RedstoneModelOracle`); nothing sleeps, so all timing error sits on the RCON side. `RedstoneModelOracle` keeps whole resident `ChunkColumn`s because dispatch reach depends on the `ChunkSource`; `without_neighbours` exists only as the control proving a cross-seam assertion has a detector.

| lane | compares |
|---|---|
| Live fixed (`differential_live_fluid_spread`, `differential_live_redstone_contraption`; `#[ignore]`) | model vs real vanilla: a water front in a closed channel; a repeater chain across two chunk seams |
| Live generated (`differential_live_generated_{fluid,redstone,piston,waterlogging}`; `#[ignore]`) | generated, shrunk, replayed `SetBlock` scripts vs vanilla |
| Tick corpus (`differential_tick_corpus`, `differential_fixed_*_production`) | production model vs recorded observations (`tests/fixtures/tick_corpus_26_2_*.json`) |
| Captured client state (`differential_captured_*`) | real adapter plus public client read model vs unmodified server packets: slots, block updates, chunk lifecycle and content, entity lifecycle |
| Generated client state (`differential_client_state`) | block/entity/inventory/container scripts through `ClientBuilder` over `memory_pair` vs independent maps |
| Hermetic models (`differential_{container_click,hopper,brewing,composter}_model`, `differential_generated_*`, `scheduled_tick_queue_model`, and similar) | a production consumer vs an independent model, fixed ChaCha seed, bounded, shrinking |

Every lane has a detector control (a deliberately wrong model or corrupted read that must fail); keep that when adding one.

**Generator.** `campaign::generation` generates and shrinks over a finite, caller-supplied position/state alphabet, emitting only `Action::SetBlock` (random raw commands are overwhelmingly invalid). It uses `proptest` strategies and `ValueTree` with a fixed seed and fixed case/shrink budgets, no time limit (not `arbitrary`, which cannot shrink semantically). A shrink is accepted only if it keeps the original `(tick, position, left, right)` class. Worst-case length `(max_steps - 1) * max_tick_gap + settle_ticks + 1` must stay within `MAX_ORACLE_TICKS` (4,096). A finding serialises as versioned JSON (minimal script, region, settle ticks, seed, divergence); unknown versions are rejected. `differential-campaign` runs sustained fluid/waterlogging/redstone/piston searches with explicit seed and budgets, an atomic checkpoint, deterministic resume (refuses changed configuration), numeric loopback endpoints only and a 1 MiB artifact cap ([resumable campaigns](fuzz-harness.md#resumable-live-campaigns)).

**Live-oracle facts (measured).** Each fails in the safe-looking direction, where a broken rig reports agreement.

- `execute if block ... run say` is blind over RCON (both arms return `''`). `RconOracle::block_state` uses terminal `execute if block <pos> <pattern>` (`Test passed`/`Test failed`) and treats other replies as oracle failure.
- `/tick step` does not advance scheduled block ticks: a water front moved one cell per 5 ticks in real time and zero across 25 freeze+step pairs. `RconOracle::advance_tick` polls `time query gametime`; `TICK_MILLIS` (50 ms) is only the poll cadence.
- Block ticks outlive the blocks that scheduled them (a ticked unpowered repeater turns on unconditionally). `settle_until_quiescent` waits for twelve consecutive unpowered ticks, with a distinct coordinate lane per test.
- `WorldOracle::begin_comparison` enables strict checks: the game-time counter must equal the nominal boundary around each action and observation group. A crossed boundary is a retryable timing failure (three attempts, each from a fresh reset), never agreement or a divergence.
- Reset must be positive: force-load, clear, wait six ticks (one more than the five-tick water delay), rebuild and verify every cell against a discriminating alternative. Cleanup always attempts clear, counter reset, drain and force-load removal.
- Every RCON connect and frame has a five-second deadline (`RCON_IO_TIMEOUT`) shared across partial socket operations. A live test must assert its read primitive discriminates in both arms, not only that the comparison returned `Agreed`.

Redstone timeline (20 cells, repeater delays 1, 4, 2, seams at hop 1 and cell 17): cell 1 reaches power 15 on tick 0, cell 16 power 8 on tick 10, cell 18 power 15 on tick 14. Reading a repeater delay as `delay` instead of `2 * delay` ticks gives 1/5/7; a flat one-tick delay gives 1/2/3. The fluid front reaches cell N on tick 5N.

**Refreshing captured fixtures.** Start the headless creative oracle, then run the lane's `acquire_*_from_external_server` ignored test with `--no-default-features --features v26-2,rcon-oracle`. It prints `*_CAPTURE=` JSON (or writes the absolute path in `LODESTONE_CHUNK_LIFECYCLE_CAPTURE_OUT` / `LODESTONE_CHUNK_CONTENT_CAPTURE_OUT`). Replace the fixture without re-encoding, keeping its provenance text. Acquisition uses ports `25570`/`25571`; never run two at once.

**Not covered.** Client-state corpora are tiny (three slot payloads, one block-update sequence, one chunk lifecycle, one palette and heightmap, one armor stand); no biome, light, initial block-entity or entity-metadata comparison. Generated live domains are fluids, waterlogging, redstone and pistons only; containers, gravity and effects are hermetic. Scheduled ticks have no client-side oracle. Comparisons are on client state, never rendered frames.

## How to change it

- **Track A target:** add `fuzz/fuzz_targets/<name>.rs` (`#![no_main]` + `fuzz_target!`) and a `[[bin]]` in `fuzz/Cargo.toml` (`test = false, doc = false, bench = false`). A missing `[[bin]]` compiles but yields no binary; check `cargo fuzz list` from `fuzz/`. CI gates it automatically.
- **Seed it externally:** add a family function to `generate-seeds.py`, run `just fuzz-seeds-regen`, commit. If no outside producer exists, say so rather than seeding from our own encoder.
- **Fuzz dependencies:** `cargo update` inside `fuzz/` (separate committed lock).
- **`Action` alphabet:** add a variant and handle it in every `WorldOracle` impl (`RconOracle`, `FluidModelOracle`, the self-check fakes). `Action::RunCommand` is a deliberate in-process no-op, never generated.
- **Generated scenario:** keep positions/states finite and caller-owned, order entries simplest first so shrinking has a direction, repeat an entry to weight it. For pistons change domain, rig and probe region together in `campaign::live_piston`; a larger action bound can push dirt past the watched region.
- **Live generator:** `search_and_shrink_with` (the evaluator owns reset, baseline, timing and cleanup; failures return as `DifferentialOutcome::OracleFailed`) plus `ReplayCase::replay_generated_with`, which validates scenario, lane, action kind and alphabet before RCON setup. Replay files are untrusted and cannot use `RunCommand`.
- **`WorldOracle`:** answer through `state_matches`, or the sides disagree on spelling.
- **Fluid regression control:** with `./scripts/live-oracles/creative.sh` running, `just fuzz-historical-fluid-reversion` applies the former delay-one seeding in a detached worktree and requires the test to find, shrink and replay the divergence. Never `git revert` in the shared checkout.

## Configuration

- `-max_total_time=N`, `-rss_limit_mb=N` on every `just fuzz-run*`.
- `just fuzz-smoke [seconds]` (default 30, positive integer up to `2147483647`); `FUZZ_SMOKE_RUNS` caps executions per target (default 10000). Short run: `CARGO_BUILD_JOBS=2 FUZZ_SMOKE_RUNS=100 just fuzz-smoke 2`.
- `LODESTONE_DIFFERENTIAL_RCON` (`IP:port`, numeric only, default `127.0.0.1:25571`). The oracle needs `pause-when-empty-seconds=0`, or a paused world runs no block ticks and reports agreement.
- `LODESTONE_DIFFERENTIAL_REPLAY` (path): replay a saved minimised case; it must satisfy the scenario's domain and probe-lane policy.
- `SearchBudget` (`seed`, `cases`, `shrink_attempts`): ChaCha RNG, no failure persistence, `max_shrink_time` zero.
- `lodestone-fuzz` features: `rcon-oracle` (off by default so `cargo test --workspace` needs no network) and `differential-campaign` (includes `rcon-oracle`, `proptest`, `serde`, `serde_json`; its arguments are explicit and ignore the env vars).

## Dependencies

`cargo-fuzz`, `libfuzzer-sys` and the pinned nightly; one leaf crate per Track A entry point (`lodestone-core`, `-model`, `-server`, `-v26-2`, `-data`, `-assets`, `-anvil`, `-net`); `lodestone-testsupport` (`RconClient`, optional); `python3` for `generate-seeds.py` and `fuzz/test_smoke.py` (neither in `just health` or CI); a live vanilla oracle under Apple `container` for `#[ignore]`d Track B tests ([Oracles and benchmarks](oracles-and-benchmarks.md)); `proptest` and `serde` dev-only.
