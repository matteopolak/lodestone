# 26.3 feature decoration

## What it is

`lodestone-worldgen-feature-26-3` runs the 26.3 `feature` and `placed_feature` registries over a chunk: it orders every biome's feature lists into the global per-step sequence, derives the per-chunk decoration seed and per-feature seed, runs each placed feature's modifiers and places the feature, bit-identical to the real 26.3 server. Every Overworld, Nether and End feature type is ported and oracle-verified (`Feature::Unported` remains for a type a future data bundle adds).

## How it works

### Core types

- `blocks::BlockTable` is the server's block-state table (`assets/block_facts.txt`, dumped by `BlockFactsOracle263`): property domains plus a fact word per state (air, replaceable, solid, occlusion, fluid, sturdy faces, light, collision up-face). A `State` is the global state id; `with(state, prop, value)` edits a property by the sorted mixed-radix layout. `tags::BlockTags` resolves bundled tags (nested `#tag` included) into bitsets.
- `env::Env` bundles both plus six per-state heightmap flags. `level::Level` is the 3x3 chunk window. `set` is the region write (keeps live heightmaps current, drops writes outside build height); `set_raw` is the section write for ore blobs (no heightmap upkeep). `WORLD_SURFACE_WG` and `OCEAN_FLOOR_WG` are frozen at terrain time; `WORLD_SURFACE`, `OCEAN_FLOOR`, `MOTION_BLOCKING`, `MOTION_BLOCKING_NO_LEAVES` follow writes. `Level::biome` zooms with the obfuscated seed and clamps quart Y to the stored range (an ore range reaching y=384 reads the top stored cell).
- `registry::Features::load` parses every placed feature; `registry::sort_features` gives each biome edges between consecutive features and a depth-first search over `(step, first-seen index)` for a reverse topological order, whose per-step list index is the feature's global index (the seed input). `Decorator::decorate` mirrors the reference loop: decoration seed from the chunk origin, then per step the sorted union of present biomes' indices, `set_feature_seed(decoration_seed, index, step)`, `PlacedFeature::place`.
- `placement::Placement::modify` appends each modifier's output; `PlacedFeature::place` recurses depth-first (a modifier's whole output is drawn before the first output is processed further). The `biome` modifier asks whether the zoomed biome lists the top-level placed feature in any step. Value providers (`provider`) and block predicates (`predicate`) parse once into enums.
- `stateprovider::StateProvider` covers `simple`, `rule_based`, `weighted`, a bare state, a bundled name, plus `noise`, `dual_noise`, `noise_threshold`, `randomized_int`, `rotated` (noise ones build a normal-noise field from the provider's seed). A rule-based provider with no answer yields `None`; `get` falls back to the existing block. A new provider is a variant plus its `parse` and `get_optional` arms.
- `survive::Kind` classifies blocks by survival rule (vegetation, double vegetation, mushroom, cactus, sugar cane, lily pad, seagrass, kelp, sturdy-below, bamboo, carpets, sea pickle, small dripleaf, spore blossom, propagule, hanging roots, coral plants/fans). An unclassified block is a gap, never a guess. Coral blocks, sculk catalyst and potent sulfur have no rule.
- Light: a column still being generated reads block light 0 and `Level::sky_light` (15 with skylight, 0 in the Nether), so an Overworld or End mushroom survives only on blocks tagged to override the light requirement, while a Nether one survives on any solid block. `climate` answers should-freeze and should-snow from biome temperature (frozen modifier and snow-line lapse in `lodestone_worldgen_core::engine::release26_3::biome`) and `has_precipitation`; snow survives on a block with a full collision up face unless tagged against it (or tagged to support it regardless).
- `Level::region_rng` is the region's own random source, used by pale moss carpet toppers. The real server seeds it from the clock (not reproducible); the oracle and engine seed it with the world seed per chunk.

### Feature families

- Lakes and springs (`feature::lake`: blob grid from random ellipsoids, checked before any write, then barrier shell and surface ice for water; `spring_feature` counts rock and hole neighbours; the placed block is the source block regardless of `falling`), `feature::disk` (x-fastest then z, which fixes provider draw order), `feature::freeze` (top-layer ice and snow).
- Vegetation: `feature::plant` (`simple_block` places both halves of double plants and copies waterlogging; `block_column`), `feature::select` (random, weighted, boolean, sequence, overlay selectors nesting a placed feature via `place_nested`), `feature::mushroom` (cap first then stem; cap provider drawn per cap block; replaces only air, leaves, mushroom-replaceable), `feature::misc` (`vines`, `bamboo`, `underwater_magma` which treats a neighbour as covering when it occludes, `block_blob`; `misc::can_attach` needs a sturdy face or full-cube collision and is shared with the tree edge pass).
- Nether (`feature::nether`): `netherrack_replace_blobs` (positions via `nether::manhattan_ordered`, depth-then-x-then-y with each `z` mirrored), `delta_feature` (clear only with air above and every other neighbour non-air), `huge_fungus` (height cap is `Level::gen_depth`, 128 in the Nether), `random_neighbor_spread`, `single_block_pillar`, `projected_random_patchy_square`, `stepped_column_cluster` (basalt columns; random sites drawn lazily, three ints each, interleaved with each column's reach draw). Plant survival is a support tag per plant; fire survives on a sturdy top face only (no flammability fact; decoration places fire only on netherrack and soul fire on its base tag).
- End (`feature::end`): `end_spike` (empty list means the seed's ten pillars via `end::spikes_for_seed`; the crystal is a server-spawned entity but its yaw draw happens here), `end_platform`, `end_gateway` (known exit attaches `PlacedBlockEntity::EndGateway`), `end_island`, `chorus_plant` (recursive, connections recomputed each write).
- Caves, oceans, ice: `feature::multiface` (glow lichen with the plain spreader, sculk vein with the stricter one; the search loop re-reads the same cell each step), `feature::ice` (`spike`, `iceberg` mixing `f32`/`f64` exactly and running at sea level, `blue_ice`), `feature::dripstone` (`speleothem`, cluster, `large_dripstone`; `Column::scan` is the shared floor/ceiling scan; table-based trig and wind offset; pointed blocks use `vertical_direction` and `thickness`), `feature::coral` (`coral_tree`, `coral_claw`: the nested feature drops one block per call, the shape stops growing on decline, shared list shuffle), `feature::room` (`monster_room`: chest loot seed and spawner mob both draw because the real region attaches block entities; chest turns toward its single solid neighbour), `feature::geode` (shells by a sum of inverse distances over a 33-cube, perturbed by `f32` noise from `engine::release26_3::noise::parity_params(-4, [1.0])`; `f64` sums; x fastest), `feature::patch` (`vegetation_patch` and waterlogged variant; surface cells in a `JavaSet` since planting iterates a hash set), `feature::root_system`.
- Sculk (`feature::sculk`): cursors (`charge_count` of `amount_per_charge` per round) take `spread_attempts` passes; sensors and shriekers may be placed, supported neighbours convert, and the cursor moves to a reachable sculk or vein within 12 blocks horizontally. It shares `multiface::Ctx`. Region writes run no neighbour updates.
- Trees (`feature::tree`): one `Run` per placement: trunk placer (`tree::trunk`: straight, forking, giant, mega jungle, dark oak, fancy, bending, upwards branching, cherry, poplar), foliage placer (`tree::foliage`), decorators (`tree::decorator`: beehive, trunk and leaf vines, cocoa, place-on-ground, alter-ground, attached-to-logs/leaves, shelf mushroom, creaking heart, pale moss), a leaf-distance pass and an edge pass. `tree::fallen` places stump and log with decorators run on the same `Run`. Roots (`tree::roots`, mangrove) run before the trunk: base raised by a sampled offset, the column below must accept roots, each side walks a random descending path, and nothing is written unless all four fit. Trunk, foliage, root and decoration positions are `javaset::JavaSet`, reproducing hash-set iteration order (bucket by spread hash, 16 buckets doubling at 75% load, insertion order within a bucket); decorators read it stably sorted by Y and the distance pass drains its seven work lists in that order, so it shows in placed blocks. `Run::update_edges` walks outer faces in the reference order and turns unsupported plants to air (a large fern whose upper half became a leaf loses its lower half); a vine re-derives faces from what it can attach to; other kinds are left alone, so a new neighbour-sensitive block near trees would be a mismatch to look for. The beehive decorator draws bee entries (2 plus a bounded draw each) because the real region attaches a block entity; the oracle uses a placeholder tag. The pale moss decorator places the pale moss patch configured feature itself, the oracle answering registry questions through a fake level.
- Structure templates: `nbt` reads gzip NBT (`STRUCTURE` bundle); `template::Template` orders blocks as the reference stores them (full-collision, then others, then block entities, each by y, x, z); `template::place_in_world` replays placement: one palette draw (even for a single palette), processors over every block first (`block_rot` draws one float per rottable block), then writes, waterlogging, edge-face shape updates (`shape::edge_faces`) and neighbour updates. `feature::structure` holds `template` (weighted entry, rotation, rotated-size offsets; desert well, sulfur springs) and `fossil` (rotation, template index, chunk-bounded placement at floor-relative depth, empty-corner check, skeleton and overlay with processor lists from `PROCESSOR_LIST`). Only rule, block-rot and protected-block processors are supported; others list as gaps.

### Gaps

`Decorator::gaps` lists, per placed feature, every feature type or block rule not yet ported. `tests/vegetation.rs` excludes exactly those on both sides (oracle argument `*,!name,...` from the ignored `print_oracle_args`), so the fixture grows as gaps close; `print_gaps` summarises.

## How to change it

- New feature type: add a variant to `feature::Feature`, parse in `Feature::parse`, place in `Feature::place`, add the type name to the oracle's `types` list in the test. Draw order is the contract: read the real placement once and keep every `nextX` call in order. Reads the real region answers with void air (outside build height) go through `Level::get`.
- New modifier or predicate: `placement::Placement`, `predicate::BlockPred`.
- Survival: `survive::classify` maps names to a `Kind`; add to `Kinds::supported` and `can_survive`.
- Debugging: the oracle accepts `+dump:<placed name>` (changed cells; also a `t bits value` line per random draw, for diffing draw sequences) and `+probe:x:y:z`; ours is the ignored `dump_feature` test (`LODESTONE_DUMP=name,cx,cz`).
- Rare features (desert wells 1 in 1000, fossils, cave springs) use `+force:<placed name>:<tries>` on the oracle and `Decorator::decorate_forced` (tests: `only = ["+force:name:tries"]`); each try uses seed `(decoration_seed, try, step)` and only tries drawing more than the rarity roll print; `+dump` with a force traces the last try. The oracle's fake level has a template manager served from jar data.
- After a version bump: `scripts/regen-worldgen-data-26-3.sh` (documents, tags) and `scripts/regen-block-facts-26-3.sh` (state table), then re-run the oracle commands in the test headers.

## Configuration

None at runtime. Verification fixtures:
- `tests/nether_end.rs`: Nether (`nether-biomes.txt` plus five single-biome layouts) and End (`the_end-only.txt`, `end-biomes.txt`) at settings `nether`/`end`, with `+force` probes for the basalt-delta spring, decorated island and return gateway; the oracle zeroes sky light for `nether` and gives the region a world-data stand-in for End crystals.
- `tests/trees.rs`: chunks picked greedily from a 144-chunk sweep over `scripts/worldgen-oracle-26-3/tree-biomes.txt` (the oracle's per-chunk sections are independent, so a subset is a valid fixture), with a wrong-seed control and a non-vacuity check on thirteen features.
- `tests/specials.rs`: `special-biomes.txt` (oceans, ice, caves, pale garden, cave biomes repeated) and `lush-only.txt` (rare azalea roots and ceiling plants). Probe layouts `desert-only.txt`, `sulfur-only.txt`, `deep-dark-only.txt`, `ice-only.txt`, `warm-ocean-only.txt` (sweep negative and positive chunks) and `windswept-savanna-only.txt`.
- Dungeons and geodes are rare without carvers, so `tests/fixtures/rooms-overworld-42.txt` and `geodes-overworld-42.txt` are chunks found sweeping `plains-only.txt` with only that type enabled; both carry wrong-seed controls.
- `tests/ore.rs`, `tests/fluids_surface.rs` (14 chunks from a 256-chunk sweep so that three underground-lake chunks, both springs, every disk and the freeze all change blocks) and `tests/vegetation.rs` (12 chunks, every ungapped feature).
- `common::reproduces` reruns a fixture under another seed and reports whether every feature line still matches, ignoring the seed-bearing chunk header, so a wrong-seed control cannot pass on the header.
- `cargo test -p lodestone-worldgen-feature-26-3 --release` (add `-- --ignored --nocapture` for timing, about 2 ms per chunk for ore families over mixed-biome terrain).

## Dependencies

`lodestone-worldgen-data-26-3` (documents, tags, state table), `lodestone-worldgen-core` (random sources, biome zoom, simplex noise; tests also use its terrain generator). `DecorationOracle263` builds the nine chunks the features step receives (fill and surface over a synthetic quart-resolution biome layout, final heightmaps primed, no carvers), allocates the real region without a server level and runs the real sorter, placer and features chunk by chunk, printing per executed feature the draw count and a hash of changed blocks plus a hash per final chunk, so a mismatch names the first diverging feature. It loads every worldgen registry from the jar's JSON, not code-built defaults, because they differ where a codec does not round-trip (the cherry foliage corner-hole chance is 0.5 in code and 0.25 in data). It answers block light as zero, drops scheduled ticks, and binds block and fluid tags from jar data (without fluid tags, water-checking blocks silently never survive). `BlockFactsOracle263` dumps the state table (bit layout in its header). A wrong-seed control must fail.
