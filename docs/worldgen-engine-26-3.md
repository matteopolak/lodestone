# 26.3 density engine

## What it is

`lodestone_worldgen_core::engine::release26_3` evaluates the 26.3 `noise_settings` terrain shape: the router's density functions in 32-bit float, the noise-based aquifer, the per-chunk fill turning density into stone, air, water and lava, the structure-terrain beardifier, and surface building (material rules, heightmap, post-processing). It is bit-identical to the real 26.3 server on every oracle fixture.

## How it works

Pipeline: JSON, `tree::Tree`, `compile::Compiler`, `sampler::Program`.

- `tree` parses a function document into a hash-consed arena (structural equality is id equality; floats compare by bits) and computes `interval::Interval` ranges and per-node axis-variation masks.
- `compile` rewrites the tree like the real compiler: holder references inlined, each cache deduplicated by raw input, zero-coordinate slices along axes a function does not vary on, constant folding and range shortcuts. Several folds change rounding (subtracting a constant becomes adding its negation; dividing becomes multiplying by the reciprocal), so they are part of the contract.
- `sampler::Program` evaluates through `value` (scalar) and `volume` (bulk), which round differently, notably in Perlin noise (bulk splits the XZ dot product from the Y gradient and caches per floor-Y) and interpolation (bulk adds an incremental step down each cell column). `Ctx` holds per-chunk cache cells whose lookup order (last scalar key, retained volume, compute) decides bits, so call order must match.
- `noise` holds Perlin, normal noise (octave table, Kahan-summed normalisation, second stack at frequency x 1.0181268882175227), legacy nether-biome noise, blended old noise and end-island simplex.
- `aquifer::Aquifer` is the fluid-level model on a 16x12x16 jittered grid; construction samples the surface-level function once as a bulk volume, later scalar requests hit that cache, and it runs in `f64` on `f32` samples.
- `settings::TerrainGenerator::load` compiles the eight router roots and optional aquifer functions for a seed. `fill_chunk` samples final density as a 16 x height x 16 volume (aquifer built first, as in the reference), then asks the aquifer per cell in z, x, descending-y order. `ChunkFill` reports density, a `Substance` per cell (default block or fluid) and cells whose fluid needs a scheduled update. `fill_column` runs the same over a 1x1 column for base-height queries; its aquifer is built over that column so it can differ from the same column in a chunk fill (both oracle-verified separately).
- Vertical anchors resolve against `max(chunk min, noise min)` and `min(chunk height, noise height)`. A rule set loaded without surface registries (`ResourceSet::from_tables` only) has no material system and `build_surface` is unavailable.

### Surface, biomes, carving

- **Material rules:** `material::parse_rule` turns a `material_rule` document into a `Rule` over an interned `StateTable`. States are keyed `name[sorted=props]`; `lodestone_worldgen::terrain263::parse_state_key` maps a key to a registry state and `Terrain263::canonical` gives the `StateId` of an engine state. Omitted properties take defaults; an unknown block or property is an error, never a substitution. New conditions or rules go in `material::Cond`/`Rule` with an evaluator in `surface`.
- **Surface:** `TerrainGenerator::build_surface` places a `ChunkFill` into a `SurfaceChunk`, runs every column through the rules, then eroded-badlands pillars and frozen-ocean icebergs. The heightmap updates on each block write and fluid blocks are recorded in per-section post-processing lists in marking order (duplicates kept). The preliminary-surface and ore-vein functions sample through the fill's own `Ctx`, so pass the `Ctx` the fill used.
- **Beardifier:** `beardifier::Beardifier` is an f32 pure-geometry `BeardifierSource`; set `Ctx::beardifier` before filling. `lodestone_worldgen::structure::beardifier` selects pieces in f64 and adapts them with `to_release26_3()`. Blending is not modelled (new worlds only).
- **Biomes** enter through a closure resolving quart coordinates (`biome::zoomed_biome` applies the real zoom; the generator derives its seed via `biome::obfuscate_seed`); `biome::BiomeTable` carries temperature and the frozen modifier. Sources live in `climate`: `ClimateTree` is a literal port of the bucketed search tree over `CLIMATE_POINTS` (dumped from the real server since the lists are generated in code); `ClimateCursor` carries its last-result hint, which breaks ties between equidistant rows, so replay queries in reference order. `TerrainGenerator::chunk_biomes` resolves a chunk as generation does (six climate fields as bulk step-4 volumes through one cached context, then a search per quart cell section by section bottom-up, then x, y, z); `biome_at_quart` is the cache-free point resolver. The End uses `BiomeSource::End` (island height from the erosion function, no climate target). Climate values quantise as `(f32 * 10000f) as i64`.
- **Carving** (`carver`): `TerrainGenerator::carve_chunk` runs a filled and surfaced chunk through the cave and canyon carvers of the 17x17 chunks around it. Each source chunk's biome (climate at its corner, Y 0, uncached) names its carver list, and each carver is seeded per source chunk with world seed plus list index. Carvers write a mask applied through the fill's own aquifer (so `ChunkFill` keeps it), skipping bedrock; dirt left bare under a carved grass or mycelium block is re-dressed by evaluating the surface rules there (`top_material`, resampling ore-vein volumes through the shared `Ctx`). Angles and thicknesses are `f32`, positions and radii `f64`, sines from the lookup table. Only the provider types the bundled carvers use are parsed (constant/uniform/trapezoid floats, constant/very-biased ints, uniform heights); others error.

## How to change it

- New density-function type: add it to `tree::Node` parsing, `compile::Compiler::compile` and `sampler::Program::value`/`volume`; write scalar and bulk arithmetic separately and add an oracle fixture exercising both.
- Never "simplify" arithmetic: an algebraically equal rewrite usually differs in the last bit and fails the hash comparison.
- Perf note: the pool's `take` no longer zeroes recycled buffers (every consumer overwrites its output) and `Ctx::reset` lets one context serve many chunks; the effect was below a loaded machine's noise floor and the oracle suites stay bit-exact.

## Configuration

None at runtime. Settings come from the embedded [26.3 worldgen data bundle](worldgen-data-bundle-26-3.md); add surface data with `ResourceSet::with_surface_data(MATERIAL_RULE, MATERIAL_CONDITION, BIOME)`. Tests: `cargo test -p lodestone-worldgen-core --release --test release26_3_density --test release26_3_chunks --test release26_3_beardifier --test release26_3_surface` (throughput: add `-- --ignored --nocapture`).

## Dependencies

`serde_json` and the crate's own `rng` module. Verification uses JVM oracles in `scripts/worldgen-oracle-26-3/` (`run.sh` runs a class in a temurin container against the cached server jar); fixtures live in `crates/lodestone-worldgen-core/tests/fixtures/release26_3/` and are regenerated with the commands in each test's header after a version bump. Every suite has a wrong-seed control that must fail.

- `DensityOracle263` hashes every router, aquifer and registry function over a scalar grid and seven volume shapes, uncached; `ChunkOracle263` the real fill's density, substance and fluid-update hashes; `ColumnOracle263`, `BeardifierOracle263` (scalar, volume, in-chunk) and `SurfaceOracle263` the column fill, beardifier and surface building. The surface oracle uses a synthetic quart-resolution biome source (`surface-biomes.txt` lists biomes, a coordinate hash mirrored in `tests/release26_3_surface.rs` picks one, so every biome-dependent rule runs) and prints a data-key to full-state-key map (`surface-states.txt`) so real block identities are compared; chunk hashes cover every block, the surface heightmap and post-processing lists.
- `CarverOracle263` runs the real fill, surface and carver steps over the real biome source, reporting after surface and after carving (`release26_3_carvers`; it binds the one block tag carving reads, since bootstrapping leaves tags empty, and its redress fixture exercises that path). `BiomeSourceOracle263` covers both biome resolvers (`release26_3_biomes`, with a brute-force-differs control for the tree) and `ClimateListOracle263` dumps the parameter lists.
