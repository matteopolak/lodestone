# Anvil import preflight

## What it is

`lodestone_anvil::import_preflight` inventories an Anvil world before native conversion. It separates source values with a typed destination, values that a lossy conversion would discard, and malformed or incompatible values that block conversion. `lodestone_server::anvil_import` consumes that decision for one bounded `WorldProperties` record, one bounded chunk record, or every present chunk in one explicitly selected terrain region file; it is not a whole-world walker or an opaque-data preservation layer.

## How it works

An import walker creates a `PreflightReport::builder()` and calls `inspect_level_dat`, `inspect_world_gen_settings`, `inspect_chunk`, `inspect_player`, and `inspect_unregistered_auxiliary_file` as it decodes each source. The builder borrows NBT only during classification. Its completed `PreflightReport` stores source identifiers, NBT paths, target-field classifications, and reasons; it never stores an unsupported NBT value or file bytes.

The current typed-destination inventory covers the current data version, default game mode, seed, and spawn block position/dimension. It reports other `level.dat` and world-generation settings fields as loss because there is no native destination for them yet. `PreflightBuilder::inspect_native_chunk` separately inventories a chunk's block-state sections, three-dimensional biomes, `MOTION_BLOCKING` heightmap, and section light arrays as supported. Block entities, scheduled ticks, structures, status, and auxiliary chunk fields are reported as loss because this bounded consumer intentionally drops them. A decoded player remains a whole-record loss because its mapping has not been specified. The report does not treat those payloads as extensions merely to make a later export reproduce them.

Malformed roots, missing required values, unsupported data versions, and non-built-in spawn dimensions are blockers. `PreflightReport::decide` requires the caller to send `LossDecision::Abort` or `LossDecision::ProceedAndDiscardUnsupported`; an acknowledgement cannot override a blocker. `anvil_import::import_world_properties` reruns this report and accepts only an `ImportAuthorization` that exactly matches the source's accepted-loss count. Missing, aborted, blocked, and stale authorizations all fail before the native backend is called.

`SupportedData` means a source value has a declared typed native destination. The metadata consumer maps those values to one native `WorldProperties` record and leaves unsupported fields absent, including the Anvil total-age field because the native day clock is not implemented. `anvil_import::import_chunk` maps only the supported chunk fields into the complete `NativeDirtyChunkRecord`; the returned report makes each dropped source field observable. `preflight_region_file` walks all 1,024 region-table entries, resolves oversized chunk sidecars from the supplied file's parent directory, and produces one aggregate report for every present chunk. `import_region_file` rebuilds that report, requires its one aggregate authorization, prepares every complete native record before opening the native transaction, then commits the prepared records as one batch. It returns the aggregate report together with seen and committed counts. Player, entity, POI, and auxiliary-file records, multi-directory world discovery, and export remain on the Anvil path until their mappings are specified.

## How to change it

Add a source field to the supported set only when the native format has a typed destination and the converter will consume it. Add a fixture-backed control for both the accepted NBT shape and the rejected alternative. If an extension becomes registered, introduce a typed extension-aware inspection path; do not change `inspect_unregistered_auxiliary_file` to retain bytes.

The bounded consumers are in `crates/lodestone-server/src/anvil_import.rs`. Keep the fixed `WORLD_PROPERTIES_KEY`, typed chunk field mapping, field-level `PreflightReport`, and exact authorization check together. `preflight_world_properties` is the payload-free metadata seam used by the operator command and must remain equivalent to the fresh preflight inside `import_world_properties`. `import_chunk_bytes` accepts one already-selected named-NBT payload. `preflight_region_file` and `import_region_file` take region coordinates separately from the path; do not infer them from a filename, because a renamed or copied source file must not shift every destination key silently. Keep their prepare-all-before-write behavior: calling the single-chunk importer in a loop would permit a later conversion failure to leave an earlier chunk committed. If the native chunk schema grows to cover entities or ticks, add those mappings to both the report and `NativeDirtyChunkRecord` input rather than silently removing a loss entry. Update the tests that use checked-in 26.2 metadata and chunk fixtures so their expected coverage remains intentional.

## Configuration

There are no flags or environment variables. The accepted source data version is `lodestone_anvil::level_dat::DATA_VERSION_26_2`; a different or malformed version is a blocking condition rather than a lossy one.

`lodestone-server anvil-convert import-metadata` is the filesystem-facing caller for the bounded world-properties record. It requires explicit Anvil-world `--source`, native `--destination`, and an identical `--native-path`; it reads only `level.dat` and `data/minecraft/world_gen_settings.dat`. The initial invocation omits `--apply`, prints a payload-free preflight and review token, and cannot open or create the native destination. A lossy report needs both `--apply` and that exact `--acknowledge` token. The command writes exactly one typed record; it does not walk terrain, player, entity, POI, or auxiliary paths. A fresh `WorldStorage::load_world_properties` reopen rejects extension payloads because version 1 has no world-properties extension consumer.

## Dependencies

The preflight module depends only on `lodestone-anvil`'s metadata wrappers plus `lodestone_core::Nbt`; its native chunk inspection remains payload-free. The native consumers additionally depend on `lodestone-storage`/`lodestone-storage-schema` through `lodestone_server::world_storage`, `lodestone_server::chunk_nbt` for the existing terrain/biome decoder, and `lodestone-world` for packed heightmap and light values. They emit no extension values and retain no unsupported source NBT.
