# Attack-range builder

## What it is

`lodestone_model::AttackRange` carries the six floating-point fields of an
item's attack-range component and exposes a named builder for constructing it.
The builder removes same-typed positional arguments from the normal decode
path while the compatibility constructor remains available to downstream
callers.

## How it works

`AttackRange::builder()` requires one setter for each field and finishes with
`.build()`. The constructor stores the values as IEEE-754 bits so the model
can retain its `Eq` implementation; accessors convert those bits back to
`f32`. The 26.2 adapter reads the six wire values and passes each through the
matching named setter.

## How to change it

Keep the builder argument names aligned with the accessors and the wire
decoder. If a field is added or reordered, update `AttackRange`, the adapter
call site, the accessor-order test, and the example in the type's rustdoc
together. Do not construct this value in a per-block or per-frame loop.

## Configuration

There are no runtime flags or environment variables. The builder is available
whenever the `lodestone-model` crate is compiled.

## Dependencies

The builder is generated by `bon` from the workspace dependency. The model
itself depends only on its existing version-free item and identifier types;
the 26.2 adapter supplies the decoded values.
