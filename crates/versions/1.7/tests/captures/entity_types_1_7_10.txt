# Entity type ids a real Minecraft 1.7.10 server (protocol 5) put on the wire.
#
# Recorded by tests/entity_types.rs against
# ./scripts/live-oracles/legacy.sh 1.7.10. Each name was handed to vanilla's
# own `/summon` over RCON at a position unique to that name, and the number is
# the type field of the spawn_entity_living / spawn_entity packet that
# followed -- accepted only when that packet's own fixed-point position
# matched the position the summon had asked for.
#
# The position match is what makes the transcript trustworthy rather than
# merely plausible. Entities summoned earlier in a run keep emitting spawns of
# their own -- a wither fires skulls, a dragon breaks blocks into dropped
# items -- so a "first spawn after the summon" rule attributes those to
# whichever name happened to be next. Measured, by recording the same run
# both ways: 26 of 59 rows picked up at least one foreign spawn inside the
# window, and for 3 of them the foreign spawn came *first*, so the weaker rule
# records a wrong id -- giant as an item, entity_horse and minecart as a
# wither skull.
#
# Rows for leash_knot and item_frame come from a separate focused run: both
# snap to the block grid rather than to the requested position, so the
# position match cannot select them. Their ids were read from a quiet world
# with one summon in flight.
#
# painting and xp_orb have spawn packets of their own that carry no type field
# at all, so there is no id to record for them.
#
# A `refused` row records the name as it was typed and vanilla's own reply
# verbatim, so a name this era does not have is evidence rather than a gap.
#
# <canonical name> <living|object|untyped> <type id>
# <name as typed>  refused <vanilla's reply>
